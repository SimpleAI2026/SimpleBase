# SimpleBase：技术与人文的视觉系统及首页重设计

> 日期：2026-11-12
> 状态：设计提案，尚未实施；色值为候选 token，需通过实际渲染与对比度检查后定稿
> 范围：首页优先，其次控制台与文档的视觉一致性；不改业务功能、权限、路由与项目级布局约定
> 取代关系：本方案取代 `ui-unslop-aesthetic-plan.md` 中的首页方向与品牌蓝选择，不抹去旧方案的执行记录
> 方法参考：unslop，Damir Sokolovsky / @heydamir，CC BY 4.0；本方案保留其克制、真实内容与逐层校准的方法，不套用其示例布局

## 1. 设计判断：现在的问题不是不够漂亮，而是没有中心思想

基于当前 `Home.vue`、`HomeDemo.vue` 与 `style.css` 的代码及页面结构，存在以下问题。这里是设计诊断，不声称完成了本轮截图评审。

1. **产品叙事分裂。** 左侧长文案、三条卖点、右侧三个页签、下方三张卡重复讲同一组内容，没有逐步展开的节奏。
2. **模板骨架明显。** 蓝色高亮标题、双栏 hero、等宽卡片、模拟终端，替换品牌名仍能属于大多数开发工具。
3. **视觉只有“技术”，缺少“创造”。** 大量边框、工具名与状态点让首页像控制台简介；人真正想做的是把一个想法变成可用的服务。
4. **自动轮播抢夺理解。** 访客尚未读完一个结果，面板就进入下一段；三段内容切换断开了同一个应用的连续性。
5. **“低成本”表达有风险。** 一桶存储不等于全部运行费用。计算、模型调用、自部署宿主等前提不能只藏在动画最后一拍。
6. **密度与留白缺乏角色。** 强制首屏撑满、卡片固定高度、移动端重复卖点，把演示推到折叠线下。空白应服务阅读，而不是填满视口。
7. **去装饰不等于设计。** 统一灰色只能消除噪声，无法建立品牌辨识。需要材料、构图、语言和互动共同形成方向。

### 本次目标

五秒内读懂：**用 AI 把 SaaS 想法做成应用，把本地 demo 带到云端，以共享存储底座降低后端模块的托管成本。**

不是把 SimpleBase 包装成泛 AI 创作工具，也不是暗示完全免费或无服务器成本。

## 2. 品牌方向：Paper & Engine（纸面与引擎）

- **产品：** 为 SaaS 开发者提供从本地开发到云端运行的 AI 工作台与后端能力。
- **性格：** 温和、可信、精确。温和体现在阅读与反馈，精确体现在命令、状态与成本边界。
- **世界：** 开发者的工作桌：纸上想法、编辑器里的代码、运行中的应用，而非机房、霓虹电路或悬浮玻璃。
- **主视觉：** 同一个订单应用经历“想法 → 本地工作区 → 云端服务”，对象始终存在，改变的是完成度和运行位置。
- **签名：** “交接线”：细线连接一个动作与真实结果；终点是状态点。只用于流程、部署与数据变化，不铺成装饰网格。

### 技术与人文怎么结合

| 人文侧 | 技术侧 | 共同规则 |
| --- | --- | --- |
| 温白纸面、自然阅读顺序、简短动词 | 墨绿操作、等宽命令、结构化资源 | 内容优先，不靠光效表达科技 |
| 首页适度舒展、展示用户的想法 | 控制台紧凑、快速定位操作 | 同一品牌，不强求同一密度 |
| 圆角有亲和力 | 表格和代码有明确边界 | 细节一致，不把所有控件变成药丸 |
| 状态变化平稳、有结果可读 | 每条输出有事实对应 | 动画解释因果，不制造等待 |

明确拒绝：紫蓝渐变、橙色满屏、仿纸噪点、手写英文装饰、泛用 3D 球体、玻璃卡片、夸张衬线大标题。

## 3. 颜色系统：温白 + 墨绿 + 少量陶土

### 3.1 主色板与使用比例

**墨绿是唯一交互强调色；陶土是首页叙事辅助色，不是第二套按钮色。**

| 角色 | 浅色候选 | 深色候选 | 使用 |
| --- | --- | --- | --- |
| 首页画布 | `#F6F3EC` | `#171B19` | 微暖纸面；无纹理、无彩色渐变 |
| 控制台画布 | `#F7F8F6` | `#151917` | 更接近中性，避免长时间工作偏黄 |
| 主表面 | `#FFFFFF` | `#1C211E` | 卡片、弹窗、编辑区 |
| 次级表面 | `#EEF1ED` | `#262D28` | 选中、输入、分组区域 |
| 主文字 | `#202923` | `#EDF1EB` | 标题、正文重点、数据 |
| 次文字 | `#526057` | `#BAC4BC` | 描述、辅助说明 |
| 弱文字 | `#667369` | `#9BA79E` | 时间、标签；依然需达到文本对比度要求 |
| 边框 | `#DDE3DA` | `#354038` | 分组、表格、控件边界 |
| 主强调色 | `#245C45` | `#A8D0B6` | 主按钮、焦点、链接、主系列 |
| 强调色悬停 | `#1B4936` | `#BDDDC6` | 不改变控件尺寸 |
| 强调色上的字 | `#FFFFFF` | `#15271B` | 必须验证 ≥ 4.5:1 |
| 强调色弱底 | `#E7EFE6` | `#263C2E` | 限于局部选中或结果区域 |
| 人文辅助色 | `#A65D42` | `#D59A7D` | 首页阶段编号或“想法”标记；不进入常规导航 |
| 辅助弱底 | `#F0E5DA` | `#352A24` | 首页很小的内容区域 |

首页面积建议：中性色 ≥ 90%，墨绿约 5–8%，陶土 ≤ 2%。不是硬性像素比例，而是评审时的视觉占比约束。控制台不使用陶土装饰。

### 3.2 语义色

| 含义 | 浅色 | 深色 | 原则 |
| --- | --- | --- | --- |
| 成功 | `#2F6B48` | `#8FC7A3` | 完成结果，不给每个图标涂绿 |
| 警告 | `#8A5C20` | `#DDBA78` | 配额、需注意条件；配文字 |
| 错误 | `#B43C3C` | `#F09A94` | 写入失败、权限错误；不能只靠颜色 |
| 信息 | `#496579` | `#A4BECC` | 必要的信息提示，不当链接主色 |

主色与成功色接近，因此通过形状、文字与位置区分：主按钮是实心控件；成功是勾选图标和完成文案。图表多系列用墨绿、蓝灰、暖灰，陶土仅在确有独立比较系列时使用。

### 3.3 token 落地策略

- `--primary`、`--ring`、`--sidebar-primary` 同步迁移至墨绿，不保留第二个蓝色品牌 token。
- `--accent` 继续表示中性选中表面，不与品牌主色混淆。
- 新增语义 token：`--text-secondary`、`--landing-background`、`--story-accent`、`--story-surface`、`--primary-hover`。只在全局主题 token 层定义，布局样式仍用 template Tailwind class。
- 首页根节点使用 `bg-landing-background`；控制台继续 `bg-background`。不把暖纸底扩散到编辑器和数据表。
- 不用 `text-primary/60` 制造十种文字颜色；主、次、弱文字均采用不透明 token。
- 在每一个实际组合上计算 WCAG 对比度：普通文字 ≥ 4.5:1、大字 ≥ 3:1；交互边界/焦点标记目标 ≥ 3:1。细分隔线可以弱于控件边界，不能误当成可点击控件的唯一轮廓。
- 禁止直接全仓替换色值。先审计图表、Monaco、Sonner、代码块和第三方交互组件的真实使用，再迁移。

## 4. 字体、尺度与材料

### 4.1 字体

**人文感来自文案与节奏，不依赖新字体。** 第一版继续离线系统字体栈；中文优先系统中文字体，英文跟随系统 sans。等宽栈保持现有 `ui-monospace / SFMono-Regular / Menlo / Consolas`。

如后续需要字体资产，另行确认授权与本地自托管；本计划不安装字体依赖、不请求 Google Fonts。中文 hero 不使用宋体拼西文衬线，避免成为廉价杂志模板。

| 场景 | 桌面字号/行高 | 手机字号/行高 | 字重 |
| --- | --- | --- | --- |
| 首页主标题 | 60–64 / 1.12 | 36–40 / 1.18 | 500 |
| 首页副标题 | 18 / 30 | 16 / 26 | 400 |
| 区块标题 | 32–36 / 1.25 | 26–28 / 1.3 | 500 |
| 能力标题 | 20 / 28 | 18 / 26 | 500 |
| 控制台正文 | 14 / 22 | 14 / 22 | 400 |
| 控件标签 | 14 / 20 | 14 / 20 | 500 |
| 元信息 | 12–13 / 18 | 12–13 / 18 | 400 |
| 代码/命令 | 13 / 22 | 12–13 / 20 | 400，mono |
| 主要数据 | 28–32 / 1.15 | 26–28 / 1.15 | 500，tabular |

标题只在 ≥ 40px 时允许 `-0.02em`；中文默认常规字距。不要把整个主标题第二行染绿：主体仍用墨色，墨绿留给动作与结果。

### 4.2 间距、圆角、阴影

- 间距基准：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 96。
- 首页容器：最大 1280px，1440px 视口两侧约 80px；内部正文块约 480px，视觉占 55–60%。超宽屏不继续无限放大标题。
- 页面边距：手机 20px（320px 下 16px），平板 32px，桌面 48–80px。
- 控制台继续全宽，沿用 `--page-pad`；不加 `max-w-*`，不改变已定稿侧栏高度与间距。
- 交互控件圆角 8px，内容卡 12px，主要演示框 16px，键帽 4px。圆形仅用于头像与状态点。
- 首页演示框浅色阴影 `0 12px 32px rgba(32,41,35,.08)`；普通卡 `0 1px 2px rgba(32,41,35,.04)`；深色使用表面台阶，无彩色阴影。
- 边框一般 1px；流程连接线 1px，不铺背景网格。图标 lucide 16–18px / 1.5 描边，图标颜色随文字角色。

## 5. 首页构图：从口号并排改成一个完整故事

保留导航、hero、能力说明、页脚的阅读顺序。能力说明区内部重新分配比例，不再做三个同构卡片。

### 5.1 首屏

桌面草图：

```text
SimpleBase                                  使用文档    进入控制台
─────────────────────────────────────────────────────────────────

为 SaaS 构建的                 ┌──── 一个持续存在的订单应用 ────┐
AI 工作台                      │ 想法    本地工作区    云端运行 │
                               │                              │
从一句需求，到一个可用服务       │   应用结果（订单 / 汇总）     │
                               │                              │
用 AI 做后端，让本地 demo        │   当前动作 → 已产生的结果    │
沿同一条路径上线                 └──────────────────────────────┘

[开始构建 →]  查看上线指南        手动前进 / 暂停 / 重播

数据库 · KV · 云函数 · 触发器 · 定时任务
─────────────────────────────────────────────────────────────────
```

这是构图意图，不是要求出现重复标题。“为 SaaS 构建的 AI 工作台”是唯一主标题，下面可以用短导语“把本地想法，交给线上运行”，不能再堆一个同字号标题。

**明确规格：**

- 导航高 72px；logo 18px；文档是文字链接，主动作 36–40px 高。不增加浮动药丸导航。
- Hero 上下留白桌面 72–96px，手机 40–48px；按内容决定高度，不强制 `100svh` 撑出空白。
- 两栏间距 48–64px；左 5、右 7 的栅格比例。标题不超过三行，中文副标题不超过约 50–65 字。
- 左侧只有标题、两句说明、一个主动作、一个次动作。删除首屏三个重复卖点的 `dl`。
- 模块名作为一条安静的能力基线，放在 hero 末尾，不各自带图标底块。
- 右侧重点是“应用结果”，不是命令。工具调用和终端输出是次级证据。视觉上至少 60% 面积给应用/工作区，命令证据最多 40%。
- 原 `S` 标记本轮可保留，但改墨绿、无阴影；标志重新设计不是阻塞项，也不新造叶子、机器人或火箭。

### 5.2 同一个应用，而不是三个互不相关的模拟窗口

演示对象：订单应用。表 `orders`、汇总函数 `daily_summary`、定时任务 `nightly` 前后一致。所有数据清楚标注“交互演示”；不展示无来源营收、用户数、性能倍数。

- **想法阶段：** 显示一句需求与应用结构，工具输出逐条产生；应用里“订单表 / 销售汇总 / 每日任务”获得完成标记。
- **本地阶段：** 显示文件树 `simplebase.json / migrations / functions` 与本地应用视图；展示实际存在的部署命令，不伪造新的发布按钮能力。
- **云端阶段：** 同一视图不消失，环境从本地变成云端；迁移/函数/任务保留，出现“已重放到云端”及可读结果。明确“一键上线”此处指已配置目标与凭据后的工作区重放，不暗示已有前端站点发布或全自动配置基础设施。
- **共享底座：** 云端结果下面用一个结构图显示五类模块汇入对象存储。讲述“共享持久化底座”，不是把每个模块右侧重复写五遍对象存储。

对象存储网站发布若需要纳入故事，先按 `object-storage-sites-plan.md` 核实能力与文档；工作区重放不自动等于前端站点上线。

### 5.3 下半页：非对称、证据优先

能力说明区依然包含三个主张，但改为有节奏的编辑式排列：

1. **AI 工作台：** 一条宽区块，左 40% 简短解释，右 60% 展示“请求 → 工具 → 资源”证据；避免再完整复制首屏动画。
2. **Demo to online：** 约占下一行 60–65%，用本地与云端工作区的并列对照，突出同一资源名；命令能完整阅读或复制，不能截断。
3. **低成本：** 约占同一行 35–40%，一张安静的架构/成本说明，不用虚构价格卡。文字明确“不必为每类模块另购托管存储”，计算与模型费用就近可见。

手机按 AI → 上线 → 成本堆叠，不横向缩小桌面画面。三段标题、解释、证据都是不同层级，不能每段再用“图标 + 标题 + 长段文字”格式。

页脚保留文档、GitHub；无虚构客户墙、星级、付费徽标或未经核实的社会证明。

## 6. 动效与交互：让人看懂，而不是让页面不停动

### 6.1 时间轴

- 首次可见时自动播放一次，建议总长 12–16 秒；完成后停留在云端结果。
- 阶段 1 约 4 秒：需求 0.5 秒可读停顿，三次工具调用依序 0.5–0.7 秒，结果停留 1.2 秒。
- 阶段 2 约 4–5 秒：本地工作区和命令同时可见，重放输出逐项出现，转换环境标签，结果保留。
- 阶段 3 约 4–5 秒：云端结果稳定，展开共享底座与成本边界。不要自动回到第一帧。
- 用户明确按重播才再播放；暂停/继续为真实按钮，悬停暂停仅作为辅助，不能是唯一控制方式。

### 6.2 动画规格

反馈 140–180ms；内容淡入 220–280ms；阶段交接 360–420ms；缓动 `cubic-bezier(.22,1,.36,1)`。只改变 opacity、transform、色值。位移 4–8px，不旋转、弹跳、缩放卡片。

应用对象保持位置，阶段切换替换证据区或环境，不用整块 `v-if` 闪切三张面板。进度是阶段状态，不把一条装饰线当加载条。未开始的区块不留大段看不懂的空白。

动画容器进入视口再启动；离开视口或切换后台停止计时。移动端尤其不能在用户看不到的地方先播完。

### 6.3 可访问性

- 减少动态：展示最终静态故事，三阶段内容可手动查看，无自动计时、无透明的可聚焦元素。
- 每个阶段有真正的可访问标题；若使用 tab，则实现左右箭头、Home/End、roving tabindex；否则采用普通步骤按钮，不套不完整的 tab ARIA。
- 隐藏阶段使用 `hidden / inert` 等正确语义；不能只 `opacity:0` 留在读屏/Tab 顺序里。
- 不把逐字代码放进 `aria-live`；完成结果最多 polite 通知一次。
- 触控目标至少 44px；主焦点环 2px + 2px offset，对白色与墨绿表面均可辨。

## 7. 文案：少一点技术摘要，多一点工作结果

### 推荐首页文案方向

- H1：**为 SaaS 构建的 AI 工作台**（保留用户确认的定位）
- 描述：**用 AI 建表、写云函数、安排任务。把本地跑通的 demo，沿同一条路径带到云端。**
- 主动作：**进入工作台**（实际路由仍指向现有云助手入口）
- 次动作：**查看上线指南**（指向真实本地开发/云端重放文档）
- 成本标题：**一个存储底座，多种后端能力**
- 成本正文：**数据库、KV、云函数、触发器与定时任务共享持久化底座，不必分别购买托管存储。**
- 就近限定：**需运行 SimpleBase 实例；计算资源与模型调用费用另计。**

“不必分别购买托管存储”与“整个 SaaS 只有存储费用”不是同一件事。即便保留用户希望突出的“只付存储费”，也必须标为存储层成本口径，并紧邻上述前提，不能隐藏在轮播或页脚。

所有界面文案落在现有中英文 locale 树。英文按英语自然表达，不逐字翻译中文；维持 key 同构，不在组件里拼句子。

## 8. 整体 UI 的延伸规则

### 控制台

- 暖意来自低饱和中性表面和清晰文案，不涂满暖纸色；墨绿仅在主动作、焦点和主系列。
- 保留侧栏 `h-11 / sm:h-9 / gap-1.5`、全宽主区、顶栏既定顺序、`w-56` 项目切换器以及 PageContainer 单行 subtitle。
- 表格表头/普通行/hover/选中/键盘焦点五态区分：表头次表面、hover 微弱表面、选中局部中性阶梯并配选择标记、焦点清晰 ring。
- 主按钮有明确 action，辅助按钮是 outline/ghost；一屏不出现多片绿色按钮。
- 加载/空/错误走现有公共组件；资源尚未建立不误报错误。刷新保留旧内容，不用整页闪白。
- 数据表、SQL、终端字号和列密度维持工具属性；数字右对齐按业务组件实现，不全局改掉既有表格对齐契约。
- `components/ui/**` 仍遵守本地 fork 约定：主题 token 迁移不意味着自由重写基础库样式。

### 云助手

消息内容比气泡轮廓重要。用户灰底、助手主表面；同一个回答内的工具与结果成组。绿色只标当前动作或确认；失败卡在可读状态停留，不默认折叠把错误藏起来。长命令可复制，文本不能因圆角或 overflow 裁剪。

### 文档

纸面气质可以稍强，但代码块保持中性。正文 16px / 28px，阅读宽度约 720–800px；标题层级靠字号/段落节奏，正文链接墨绿并带下划线。侧栏密度与控制台不同，但圆角、焦点、主色同源。

## 10. 验收：不是“比以前干净”，而是“能看懂并愿意使用”

### 设计门槛

- [ ] 五秒测试：读者能说出 AI 工作台、本地到云端、共享存储底座三件事；不需要读终端命令才知道产品做什么
- [ ] 品牌测试：去掉 logo，暖纸面、墨绿动作、连续应用交接仍有同一身份；不是另一种 SaaS 模板
- [ ] 叙事测试：演示始终是同一个应用，每步有输入、动作和结果；页面不会在读到一半自动重置
- [ ] 成本测试：访客不会误以为无计算、无模型、无宿主费用；“一键上线”的前提明确
- [ ] 密度测试：移动端演示尽量在首屏附近出现，无重复卖点把它推到很远；不为此缩字号或隐藏重要说明
- [ ] 状态测试：未播放、播放中、暂停、完成、手动切换五态均能独立理解

### 工程门槛

- 视口：320 / 390 / 768 / 1024 / 1440 / 1920；明暗两主题；浏览器缩放 200%。
- 字体：中文/英文、系统回退字体；英文长标签不溢出。命令可横向滚动或换行，不能截断唯一关键命令。
- 对比度：用实际 token 组合计算并在执行记录中填入比值，不凭“看起来清晰”验收。
- 性能：不引入大图或外部字体请求；不因每拍动画触发全页布局；离开页面销毁定时器和 observer。
- 单测：一次性结束、暂停继续、重播、手动阶段切换、视口不可见、后台暂停、组件卸载、reduced motion、键盘操作、locale 同构。
- 构建：`cd ui && yarn build`；测试 `cd ui && yarn test`。不得下调覆盖率阈值或跳过失败用例伪装通过。
- 若全量有既有失败，记录准确文件、错误与基线证据；不顺便修改无关文档或业务。
- 截图：首页全页与三个演示阶段；控制台云助手/大盘/数据表；文档。逐阶段限量渲染，重点比较构图、阅读顺序和状态，不只检查有没有 overflow。

## 12. 色彩复核与首页线框（2026-11-12 补充）

> 方法：用 WCAG 2.1 相对亮度公式逐对计算 §3 的候选色值，并换算 HSL 看色相是否一致。只做了计算，没有渲染截图。下文的「修订值」同样经过计算，可以直接替换 §3 中对应的候选值。

### 12.1 结论

方向成立（暖色纸面 + 墨绿操作 + 少量陶土），但 §3 的色值有 **4 个必须修的问题**，另有 2 个要注意的地方。

| # | 问题 | 证据（对比度 / 色相） | 影响 |
| --- | --- | --- | --- |
| 1 | **纸面暖、灰阶偏绿，两者打架** | 画布 `#F6F3EC` 色相 H42（暖黄）；次级表面 `#EEF1ED` H105、边框 `#DDE3DA` H100、文字 `#526057` H141 都偏绿 | 首页上白卡和分隔线会呈现灰绿色，压在暖纸上显得发脏。「人文」变成「旧」 |
| 2 | **浅色弱文字没达标** | `#667369` 在画布上 4.49、在次级表面上 4.37（要求 ≥ 4.5） | 时间、标签、说明文字不合格 |
| 3 | **陶土色当文字用不合格** | `#A65D42` 在画布上 4.44、在自身弱底 `#F0E5DA` 上 3.97 | 阶段编号、「想法」标记读不清 |
| 4 | **成功色和主色分不开** | 浅色 `#245C45` 与 `#2F6B48` 对比只有 1.23，色相 H155 与 H145 几乎相同；深色同样只有 1.14 | 「完成」和「可点击」长得一样，状态语义失效 |
| 5 | 边框只能当分隔线用 | 浅色边框与画布 1.18、与白卡 1.31 | 用作分隔线没问题；但输入框、未选中开关这类控件边界需要 ≥ 3:1，必须另设一个 token |
| 6 | 主色弱底色相错位 | `#E7EFE6` 是 H113，主色是 H155 | 选中底看起来偏黄绿，和按钮不像同一种颜色 |

**及格的部分（保留）：** 主文字 13.5–15、次文字 ≥ 5.8、白字在主色上 7.80、深色主色上的深字 9.24、深色全套文字 ≥ 5.6、警告/错误/信息在浅色下 ≥ 5.0。

**另外说明：** 线上 `ui/src/style.css` 仍然是石墨灰阶 + 蓝色 `#2563eb`，本计划还没有落地。现在的首页是「中性灰 + 蓝」，正是 §1 指出的模板感来源。

- 陶土色只用于首页的阶段编号和「想法」标记，**不做链接、按钮和图表系列**。
- `--border` 继续表示分隔线；新增 `--control-border` 给输入框、复选框和未选中开关。不把分隔线加深来凑数，否则整页线条会变重。
