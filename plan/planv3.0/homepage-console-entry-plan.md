# SimpleBase 科技感主页与控制台入口计划

> **状态**：plan-only；本文件只定方案，不修改产品代码。
> **范围**：`ui/src` 的公开主页、路由入口及必要回归测试。
> **关联**：`ui/src/router/index.ts`、`ui/src/layouts/DefaultLayout.vue`、`ui/src/layouts/DocsLayout.vue`、`ui/src/style.css`、`ui/src/pages/Dashboard.vue`。

## 0. 目标与锁定决策

为 SimpleBase 增加一个独立的产品主页：视觉上有科技感，但继承现有暖橘主色与深浅主题；主页右上角始终有清晰可见的「控制台」入口，点击后进入**当前控制台的监控大盘**，而不是重做控制台。

- `/` 为新的公开主页，不加载控制台侧栏、项目切换器或登录弹窗。
- 现有 `dashboard` 路由名、`Dashboard.vue`、`DefaultLayout.vue` 保留；控制台统一挂到 `/console` 下，监控大盘为 `/console`，其他页面依次为 `/console/databases`、`/console/s3` 等。
- 主页入口使用 `<router-link :to="{ name: 'dashboard' }">控制台</router-link>`；不以 `/` 作为控制台地址。未登录进入时沿用 `DefaultLayout` 的 `authStore.bootstrap()` / `LoginModal`，不新增身份认证流程。
- 这次只做主页与入口迁移，不新增后端接口、依赖或新的产品功能；本文不实施代码。

## 1. 现状及路由迁移影响

- `ui/src/router/index.ts` 当前在 `/` 下挂 `DefaultLayout`，空子路径即 `dashboard`；`/docs` 独立使用 `DocsLayout`。新主页不能作为原控制台布局的子页，否则仍会出现侧栏和登录弹窗。
- `/settings` 目前重定向 `/?settings=1`，由 `DefaultLayout.vue` 读取并打开设置弹窗；移动控制台后必须改为 `/console?settings=1`，并保留现有 query 参数和 tab 选择行为。原先保存的 `/?settings=1` 书签需单独兼容：仅此类带 `settings` 参数的旧根地址重定向到 `/console?settings=...`，普通 `/` 必须展示新主页；避免重定向循环。
- `/sql`、`/data`、`/llm` 当前是旧入口重定向；分别迁移目标到 `/console/databases`、`/console/databases`、`/console/agents`，仍保持跳转有效。对已分发的旧控制台直链（如 `/databases`、`/agents`、`/logs` 等）按原路径映射重定向到 `/console/*`，保留 query，避免用户收藏夹失效；不要把历史根路径 `/` 无条件重定向到控制台。
- `ui/src/layouts/DocsLayout.vue` 的品牌入口和「返回控制台」目前都指向 `/`：品牌入口可回新主页，明确写着「返回控制台」的链接必须改为 `{ name: 'dashboard' }`。
- `ui/src/components/NavMenu.vue` 已按路由名生成侧栏，无需改变分组与 `dashboard` 名称；但要核对测试、各页面中写死的绝对路径与导航链接。

## 2. 视觉与内容方案

### 2.1 视觉语言

沿用 `ui/src/style.css` 语义 token：浅色 `--background: #f5f4ef`、深色 `--background: #1a1918`、共同的 `--primary: #d97757`，并以 `foreground`、`muted`、`border`、`card` 做层次。科技感通过细网格/点阵、边框、柔和光晕、控制台式数据示意与小型终端排版表达；克制使用橘色强调，不改成与产品脱节的蓝紫霓虹或增加新的全局配色。示意内容标注为产品能力展示，不伪装成实时运行数据。

- 顶栏：左侧 SimpleBase 品牌，右上角「控制台」主操作；窄屏仍可见、可点击，保持品牌与 CTA 间距。
- 首屏：一句明确的产品定位、简洁说明、进入控制台的主 CTA；右侧以纯前端、静态且可访问的产品示意展示数据库 / S3 / 云函数 / Agent 等能力，不需要请求 API。
- 次屏：3–4 个现有能力模块的简短介绍，可链接到对应文档；不要承诺代码尚不支持的能力。页脚保留文档与 GitHub 等确有目标的链接。
- 使用 Tailwind v4 的 template class 和现有 UI 基础组件，不新增 CSS 文件或依赖；装饰层 `aria-hidden`，正文对比度和键盘焦点明确。动效仅作渐入/轻微漂浮，遵循既有 `prefers-reduced-motion`，低性能设备和小屏不应依赖动效呈现信息。

### 2.2 主题与响应式

主页直接复用 `App.vue` / `settings` store 已有 light / dark / system 切换机制，不再实现第二套主题状态；无用户设置时依当前应用规则显示。验收桌面和手机宽度、浅色/深色、系统主题切换及减少动态效果下的布局；避免首屏水平溢出或按钮被折叠。

## 3. 分阶段实施（后续执行时）

### 阶段 A：路由和入口

1. 在 `ui/src/router/index.ts` 注册独立 `home` 路由：`path: '/'`、`meta.title: '首页'`、`meta.hidden: true`，懒加载 `ui/src/pages/Home.vue`；原 `DefaultLayout` 父路由移到 `/console`，空子路径仍为 `dashboard`，其余子路由保持名称、权限 meta 和原有结构。
2. 处理 `/settings`、`/sql`、`/data`、`/llm`、旧控制台直链及旧 `/?settings=...` 的兼容规则；确认首页只渲染主页，`/console` 仍进入原有控制台并触发原登录行为。对控制台内部导航采用命名路由，避免将来再次移动路径时遗漏。
3. 更新 `DocsLayout.vue` 的「返回控制台」目标，检查项目中指向旧控制台绝对 URL 的其余入口（不盲改测试 helper 内的模拟路由）。

### 阶段 B：主页界面

1. 新建 `ui/src/pages/Home.vue`，实现顶栏、Hero、产品示意、能力概览和页脚；右上角和 Hero 按钮均跳到现有 `dashboard` 命名路由。
2. 用现有语义主题色及组件完成浅色/深色视觉；不向公开主页引入 `DefaultLayout`、真实项目数据请求或登录弹窗。静态内容与现有功能、文档一致。
3. 检查移动端布局、交互命中区域、语义标题层级、按钮可访问名称、键盘焦点及 reduced-motion。

### 阶段 C：测试与验收

1. 更新 `ui/src/router/index.test.ts`：`/` 解析到 `home`，`dashboard` 解析到 `/console`，主要控制台路径及 legacy redirect 解析正确；验证 `/settings` 和旧 `/?settings=...` 的 query 保留，不产生重定向循环。
2. 新增主页组件测试：品牌与首屏信息可见、右上角「控制台」及首屏 CTA 跳至 `dashboard`、装饰元素不干扰可访问名称；核对 `DocsLayout` 的「返回控制台」链接。
3. 回归 `DefaultLayout` 登录弹窗/设置 deep-link、`NavMenu` 选中态，以及直达 `/console`、刷新 `/console/databases`、从主页进控制台的前进/后退行为；不修改无关单测中的假路由以凑通过。
4. 在 `ui/` 下执行针对性 Vitest、`npm test`（覆盖率）及 `npm run build`，并进行浅色/深色、桌面/手机和未登录手工验收；测试失败先定位原因，再修复，不降低现有覆盖率阈值。

## 4. 完成标准

- 打开 `/` 可看到独立科技感主页，颜色与现有主题一致，桌面和手机均无关键内容遮挡。
- 右上角「控制台」能进入 `/console` 下的**原有**监控大盘；未登录时仍按现有方式弹出登录界面，登录后控制台可继续使用。
- 控制台侧栏、文档返回入口、设置弹窗 deep-link、旧入口跳转均正常；`/` 不再触发控制台登录弹窗。
- 深浅色与系统主题表现正常，减少动态效果时信息完整，键盘可操作；测试与构建通过。

## 5. 风险与边界

| 风险 | 处理 |
|---|---|
| 根路径原本就是监控大盘 | 不覆盖或重命名 `Dashboard.vue`；只迁移其 URL，保留 `dashboard` 路由名与布局。 |
| `/settings` 指向新主页导致弹窗失效 | redirect 改到 `/console` 并覆盖 query、tab 的回归用例。 |
| 深层旧链接或浏览器直达 404 | 为已存在的旧控制台绝对路径建立显式 redirect；确认 SPA 服务器 fallback 保持可用。 |
| 主页视觉与控制台割裂或暗色不可读 | 只使用现有主题语义 token，并分别检查 light、dark、system 和窄屏。 |
| 主页误触发真实业务数据或登录 | 页面只展示静态能力说明，认证初始化仍由 `DefaultLayout` 接管。 |
