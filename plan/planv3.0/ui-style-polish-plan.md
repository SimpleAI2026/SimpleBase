# SimpleBase UI 样式美化与可用性优化计划

> **状态**：plan-only；仅分析并制定方案，不修改 `ui/src` 产品代码。
> **范围**：`ui/src` 的首页、控制台、文档站以及共享组件；不修改 API、权限模型和产品业务流程。
> **依据**：基于当前代码的静态检查；已计算部分不透明色值的对比度，但半透明背景、实际视口溢出、主题和键盘体验仍需在浏览器中验证。
> **关联**：`plan/planv3.0/homepage-console-entry-plan.md` 已对应当前 `/` 主页、`/console` 控制台、`/docs` 文档站的路由结构。本计划是在已有主页和主题之上打磨，而非重新建设主页。

## 1. 目标与设计边界

- 统一三个入口的视觉语言：保留 `ui/src/style.css` 中的暖橘品牌意象、中性背景、语义状态色、圆角和 Inter / 衬线标题；调整不达标的文字/按钮用色，保留 light / dark / system 三种主题。
- 优先保证 320–390px 窄屏上关键内容、当前项目和主要操作可见或易于到达；桌面维持现有高密度工作台效率。
- 用一致的标题层级、间距、表格密度、状态反馈和焦点样式提升精致度，不依赖大面积渐变、额外动画或新的 UI 框架。
- 保留现有路由名、侧栏权限、数据请求、弹窗行为及表格/编辑器能力；不为美化增加依赖或重写业务页面。

## 3. 样式与交互规范（实施时落地）

1. **颜色与层级**：保留暖橘品牌意象，但把「装饰主色」「浅色主题可读强调文字」「实心 CTA 背景/前景」分开核定，不要求三者共用一个 token。浅色文字强调色可从 `#a84627` 开始试验（与现有 `#f5f4ef` 背景按不透明色计算约 5.34:1），**仅作候选**；在卡片、透明叠层、hover 和 dark 背景下逐项复测。`card` / `muted` / `border` 区分卡片与次级面板；`success` / `warning` / `destructive` 只表达语义，特别核查小字与徽标。目标为普通文字至少 4.5:1，必要的非文字交互边界及状态指示至少 3:1；disabled 态按实际用途和可识别性评估，勿机械套用普通文字标准。
2. **排版与节奏**：首页保留衬线 hero 和能力标题；控制台正文沿用约 14px 的现有基线，重要说明不使用难读的 10px 字号，ID、路径与数字使用等宽/等宽数字。顶栏提供当前位置，内容区避免重复的大标题；页面标题、简短说明、主操作明确主次。按页面区块、卡片内部、字段间距建立三档尺度，沿用现有 Tailwind spacing 优先，先在三页验证再抽取共享规范。保留 `Card`、`SbEmptyState`、`Skeleton` 等现有组件，不为统一外观增加大量页面级样式。
3. **响应式数据呈现**：按内容拥挤程度选择断点。桌面保留列信息和高密度操作；窄屏优先显示名称、状态与高频操作，次要字段可分组或展开，**不要默认所有页面都改卡片**。截断名称/ID/导出函数需有键盘和触控可获取完整内容的方式，不能只依赖悬停 Tooltip。保留横向滚动时增加适当提示，检查焦点、弹层不被裁切；避免全局 `overflow-hidden` 掩盖问题。
4. **交互与反馈**：交互控件统一检查默认、hover、focus-visible、选中、disabled、loading、empty、error；只在实测确有问题时调整现有 outline，避免组件 ring 叠加。可点击徽标使用按钮语义和可见键盘焦点；图标操作须有可访问名称，危险操作保持明确确认；表单标签/说明/错误信息与控件关联。动效沿用已有 `prefers-reduced-motion`，不用额外动画掩盖反馈。
5. **控件和触控密度**：小屏按钮与菜单入口保持易触达、间距足以防误触；列表操作顺序与权限限制跨桌面/移动端一致。按实际设备测试目标尺寸，不能仅凭 CSS 高度推断可操作。

## 4. 分阶段实施

### 阶段 A：真实基线与 P0 配色（先做）

1. 在 `/`、`/console`、`/console/databases`、`/docs` 及云函数/Agent 实际路由（以路由配置为准）采集 320、375、390、768、1280px 的 light/dark 截图；额外验证 system、200% 缩放、长项目名、长文件名、空/加载/错误态。每个问题记录视口与主题、复现步骤、前图及预期；区分**已确认的代码问题**和**待实测的视觉假设**。
2. 优先检查 `style.css` 的 `--primary`、`--primary-foreground`、文字链接和 `success`/`warning`/`destructive` 在真实背景下的合成颜色，给出 light/dark 各角色 token 映射；用可读强调色或调整实心 CTA 的背景/前景解决浅色主题对比度，避免只修链接而漏掉按钮。回归首页、选中 tab、徽标、图表和 hover/focus；记录测量值。
3. 盘点共享 Button / Input / Select / Dialog / Table 与全局 `focus-visible`：保留已有可见焦点，仅修复被裁切、双圈或缺失的实际问题；不强制全局最小宽度或 `overflow-hidden`。基线和 token 调整可以并行于后续页面方案设计，但应在视觉微调前完成验收。

### 阶段 B：P0 交互语义与表单可操作性

1. `AgentManager.vue` 中把 Agent 选择按钮与编辑/定时/删除操作拆为并列区域，共享原操作函数、权限与确认逻辑；选中态同时有可见和可读状态。工具选择徽标改为可聚焦、可用 Enter/Space 操作且有选中状态的控件。
2. `GoFunctions.vue` 的导出函数复制徽标改为按钮语义，保证截断时仍可获取函数全名和复制反馈；不依赖鼠标 hover 的 `title`。检查已有表格操作顺序和小屏触达性。
3. `CronJobModal.vue` 为输入及 Select 触发器关联标签，必要时关联说明和错误提示；cron 表达式/预设与间隔值/单位在 320px 换行或上下排列，保持 UTC 说明与保存规则不变。

### 阶段 C：P1 控制台布局与数据页

1. **仅在基线证实需要时**调整 `DefaultLayout.vue` 顶栏和 `GlobalProjectSwitcher.vue`；保留侧栏入口、当前位置、当前项目及用户入口，次要操作继续可从侧栏或明显菜单触达，不改变权限/路由。核查现有设置/刷新名称和移动端触控目标，而非重复补 `aria-label`。
2. 以已有 `Databases.vue` 移动卡片作为对照，检查长名称、操作换行、ID/时间占用和展开态；只有密度实测过高才把次要字段移到详情。先验证 `GoFunctions.vue` 六列表格、截断函数和操作可发现性，再检查 `S3Manager.vue`、`Users.vue`、`KeyValue.vue`、`CronJobs.vue`、`Logs.vue` 等。优先局部滚动提示/布局调整；确需双视图时复用数据、权限、筛选、分页及操作，桌面不丢字段。
3. 在 `Dashboard.vue`、`Databases.vue`、`GoFunctions.vue` 试用标题/说明/主操作布局规范；只有多页确实能复用时再扩展 `PageContainer.vue`。不要在顶栏与内容区重复大标题或把主操作挤出可见区域。

### 阶段 D：P2 首页、文档与图表收尾

1. `Home.vue` 保留 hero、产品能力示意和现有控制台/文档 CTA；核查小屏标题换行、卡片内边距、按钮焦点与品牌文字对比度。评估手机端文档 CTA 的可发现性，若已足够则不新增导航；产品示意仍明确为静态示意。
2. `DocsLayout.vue`、`DocsWiki.vue` 检查模块 tab 横滚是否可发现、切换后选中项是否可见、正文/代码块阅读宽度和标题层级；移动页面选择器已有名称，只在需要时把可见说明与控件关联。
3. `TrendChart.vue` 已有主题观察、不同线形、摘要和销毁逻辑：先实测 light→dark→light、system 跟随系统变化、窗口 resize、窄屏轴标签和 tooltip；只有实际失败时才修观察/渲染，不重复加入监听。

### 阶段 E：回归与交付

1. 补/更新受影响的 Vue/Vitest 测试：Agent 选择与独立操作、工具/函数徽标键盘语义、表单标签关联及原有行为；若实际修改导航、数据库展开或图表，才更新相应测试。检查移动/桌面视图的信息与操作均存在于正确 DOM 分支；jsdom 无法证明真实 CSS 布局。
2. 在 `ui/` 先运行受影响组件的定向 Vitest，再执行 `npm test` 和 `npm run build`；保持现有覆盖率要求与路由、权限、分页、项目切换、弹窗回归。计划阶段不声称这些检查已经通过。
3. 人工验收：Tab/Shift+Tab/Enter/Space/Escape、触控操作、light/dark/system、减少动态效果、320–390px 溢出及 1280px 密度、200% 缩放、长文案/长项目名、空/加载/错误态。对每处改动保留前后截图与对比度测量值，并记录未通过项。

## 5. 完成标准

- `/console`、`/console/databases` 与受影响的数据页在 320、375、390px 下，导航/当前项目及名称、状态、高频操作能找到并操作；需要横滚时有可发现提示，不裁切焦点或弹层；1280px 桌面列信息和效率不退化。
- 首页、控制台、文档站在 light/dark/system 下语义色一致；按实际背景合成色实测普通文字至少 4.5:1、必要的非文字交互边界及状态至少 3:1，特别覆盖浅色 CTA、文字链接、小字和选中态；键盘焦点可见。
- Agent 选择与编辑/定时/删除为独立可操作控件；工具选择与函数复制可经 Tab、Enter/Space 使用；定时任务的标签、说明、错误提示关联清楚，320px 表单不挤压关键内容。
- 图表在手动切换主题和 system 系统色变更后无需刷新即可更新颜色，趋势摘要和请求/错误区别可读；已存在的主题观察实现只需实测通过，无需重复开发。
- 路由、权限、项目切换、页面操作、登录与设置弹窗行为不退化；实施后 `npm test`、`npm run build` 通过，浏览器截图、对比度记录与未通过项有据可查。

## 6. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 浅色品牌色与可读文字/CTA 共用 token，导致改色牵连组件 | 按角色拆分 token，检查背景叠层与 light/dark 下链接、徽标、按钮和图表的实际合成色；候选值只有实测达标后才能采用。 |
| 移动端卡片与桌面表格两套视图引发功能漂移 | 优先优化现有数据库卡片和横滚表格；确需新增视图时复用同一数据、筛选、分页、权限和操作函数。 |
| 拆开 Agent 嵌套按钮或改动徽标语义破坏现有操作 | 保留原事件及权限、确认流程；针对选择、编辑、删除、复制和键盘操作补回归测试。 |
| 全局焦点或表单标签调整影响第三方组件 | 先验证现有规则，优先局部修复；核查 Button/弹窗/Select 触发器的焦点、标签绑定和双重 ring。 |
| 重写现有图表主题观察引入 ECharts 生命周期问题 | 图表主题观察作为验证项，只有失败时才改；改动时保持实例、resize 与卸载清理逻辑。 |
| 美化导致信息密度下降或更难扫描 | 不减少桌面表格字段；窄屏只移动次要信息，高频操作保持易触达。 |
| CSS 截图或可访问性无法由静态代码或 jsdom 测试证明 | 明确代码结论与待浏览器验证假设；未实际运行的测试、对比度和人工验收不得标记完成。 |
