# Ops Governance Specification

## Purpose

定义备份创建与恢复、审计脱敏边界、系统日志选择性记录、健康检查与延迟指标，以及项目与全局设置和迁移状态端点的契约，使生产环境可观测、可审计、可恢复且不泄露敏感内容。

## Requirements

### Requirement: 备份与恢复

备份 SHALL 支持定时创建、列举、下载、删除与恢复；恢复 MUST 使用项目管理员权限并写审计。S3 故障时 MUST NOT 静默返回「已持久化成功」，必须向调用方暴露失败或降级状态。

#### Scenario: 备份上传失败
- **WHEN** 快照上传 S3 失败
- **THEN** 备份条目标记为失败并返回错误，不宣称备份可用

#### Scenario: 恢复备份
- **WHEN** 管理员选择一个成功备份并恢复
- **THEN** 项目数据回到该备份状态，审计记录操作者与备份标识（不含数据内容）

### Requirement: 审计只记元数据

审计 SHALL 只记录 SHA-256、标识与元数据，MUST NOT 记录 SQL 参数、LLM 正文、密钥或请求体原文。`agent.trace_log` 是唯一例外，且只写 zap 日志、不写系统库 logs 表。

#### Scenario: 记录写操作
- **WHEN** 用户执行 SQL 或文档写入
- **THEN** 审计含语句哈希、项目、主体与结果，无法从审计还原参数或数据

#### Scenario: 查看审计
- **WHEN** 管理员查询审计列表
- **THEN** 返回元数据；敏感列按系统库脱敏规则置空

### Requirement: 健康检查与指标

服务 SHALL 提供存活与就绪探针；就绪探针 MUST 反映系统库等关键依赖状态，且不得产生写副作用。指标端点 SHALL 暴露 HTTP 延迟与业务计数；延迟直方图 MUST 在无样本时返回 `null` 而非 0，且 MUST NOT 输出 Infinity/NaN。

#### Scenario: 系统库不可用
- **WHEN** 就绪探针运行时系统库连接失败
- **THEN** 返回 503 并给出依赖原因，恢复后自动回到 200

#### Scenario: 无请求样本
- **WHEN** 某延迟分位在统计窗口内没有样本
- **THEN** 对应值为 `null`，不以 0 冒充

### Requirement: 日志选择性记录与查询

系统日志 SHALL 只记录写操作、错误与慢请求，避免读路径写放大；日志查询与导出 MUST 受项目范围与系统库只读约束。

#### Scenario: 普通读请求
- **WHEN** 一次查询在阈值内成功返回
- **THEN** 不写入系统库请求日志

#### Scenario: 慢请求
- **WHEN** 请求耗时超过慢请求阈值
- **THEN** 记录脱敏后的元数据，可从日志列表检索

### Requirement: 设置与迁移状态

项目级与全局设置 SHALL 经同一套校验后持久化；迁移状态端点 MUST 只读展示当前 schema 状态，不执行迁移。系统库表结构的唯一来源是 `schema.go` 的最终态建表，不得新增版本化迁移或 `ALTER` 补列。

#### Scenario: 修改全局设置
- **WHEN** 管理员更新全局设置
- **THEN** 校验通过后持久化，项目级设置不被覆盖

#### Scenario: 查询迁移状态
- **WHEN** 任意用户调用迁移状态接口
- **THEN** 只返回状态与计划，不修改数据库
