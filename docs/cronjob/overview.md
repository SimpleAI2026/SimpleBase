# 定时任务（Cron Jobs）

> 定时任务到点自动调用项目内云函数的导出函数。参考 Supabase Cron Jobs 的定位，面向「数据汇总、缓存预热、周期清理」等无人值守场景。

## 核心概念

- **任务（Cron Job）**：一条调度配置 + 一个目标（某云函数文件的某导出函数）+ 一份固定入参 JSON。
- **运行记录（Run）**：每次执行的落库记录，含状态、耗时、错误与返回值（截断 4KB）。
- **调度器**：服务端后台循环（30s 扫描）到期执行；手动「立即执行」不改排期。

## 两种时间模式

| 模式 | 配置 | 语义 |
|---|---|---|
| 定时执行（cron） | 5 字段 cron 表达式 | 分 时 日 月 周；一律 **UTC**、分钟粒度。支持 `*`、`*/n`、`n`、`a-b` 与逗号列表。示例 `0 2 * * *` = 每天 02:00 UTC |
| 固定间隔（interval） | 数值 + 单位（分钟/小时/天） | 每 N 分钟/小时/天；范围 1 分钟 ~ 30 天。以**认领时刻**为基准推进（长任务不会错位压缩） |

## 限制与语义（必读）

1. **时区**：所有时间 UTC 存储与计算；cron 表达式即 UTC 语义（与 pg_cron 一致）。控制台展示本地时间。
2. **目标约束**：保存时校验目标云函数存在且函数已导出；之后云函数被删除/改名不会自动清理任务——列表红标「目标函数缺失」，执行照常发起并记失败。
3. **入参不做类型校验**：`input_json` 保存时仅验证合法 JSON（≤8KB）；与函数签名不匹配在执行时记 failed（ErrBind）。struct 入参用 JSON 对象，基本类型入参用对应 JSON 字面量。
4. **执行超时**：10 秒（云函数解释器内部上限），超时记 failed。
5. **补跑语义**：服务重启后，已到期未执行的任务会立即补跑一次（at-least-once），不追溯历史漏跑。
6. **失败不重试**：单次失败即结束，等待下一次排期；无连续失败自动禁用。
7. **手动触发**：异步执行（202），与排期互不影响；同一任务执行中重复触发返回 409。
8. **系统项目**（admin）不支持定时任务。

## 控制台操作

1. 侧栏「定时任务」→「新建定时任务」；
2. 填任务名（字母开头，可含 `-`/`_`，创建后不可改）与描述；
3. 选择时间模式并配置（cron 可用常用预设）；
4. 选择云函数文件 → 导出函数（两级联动）；
5. 可选填入参 JSON，保存即生效，`下次执行` 时间由服务端计算回显。

列表页可直接启停（Switch）、立即执行、查看运行记录、编辑与删除。运行记录抽屉展示每次执行的返回值/错误并支持复制。

## API 概览

前缀 `/v1/projects/:projectID/cron-jobs`：GET 列表 / POST 创建 / GET 详情 / PATCH 更新 / DELETE 删除 / `GET :id/runs` 记录 / `POST :id/trigger` 手动触发。完整契约见 [`plan/planv2.0/proto-http.md` §3.14](../plan/planv2.0/proto-http.md)。
